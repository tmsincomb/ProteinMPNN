## Code Example Guidelines

**IMPORTANT**: When presenting code examples, ALWAYS add inline comments clarifying:
1. **File origins**: Whether files are built-in, user-provided, or will be created
2. **Parameter sources**: Where values come from (user input, previous steps, etc.)
3. **Output destinations**: What will be created and where

Example format:
```bash
python helper_scripts/parse_multiple_chains.py \
    --input_path=your_pdb_folder/ \  # YOUR FOLDER: Contains your PDB files
    --output_path=parsed.jsonl       # WILL CREATE: New file in JSONL format
```

File origin indicators to use:
- `BUILT-IN`: Comes with ProteinMPNN
- `YOUR FILE/FOLDER`: User must provide
- `FROM ABOVE`: Created in a previous step
- `WILL CREATE`: Will be generated by this command
- `PARAMETER`: Tunable value with explanation

## Overview

ProteinMPNN is a deep learning model for protein sequence design using message passing neural networks. This is a fork of the original repository with added support for Apple Silicon Metal Performance Shaders (MPS).

## Common Development Commands

### Running ProteinMPNN

Basic protein design:
```bash
python protein_mpnn_run.py \
    --pdb_path inputs/1QYS.pdb \
    --pdb_path_chains A \
    --out_folder outputs/ \
    --num_seq_per_target 10 \
    --sampling_temp "0.1"
```

Parse multiple PDB files:
```bash
python helper_scripts/parse_multiple_chains.py \
    --input_path=inputs/PDB_monomers/pdbs/ \
    --output_path=outputs/parsed_pdbs.jsonl
```

Design from parsed structures:
```bash
python protein_mpnn_run.py \
    --jsonl_path outputs/parsed_pdbs.jsonl \
    --out_folder outputs/ \
    --num_seq_per_target 2 \
    --sampling_temp "0.1" \
    --batch_size 1
```

### Running Tests

Run MPS performance tests:

python test_mps_proteinmpnn.py

Run MPS vs CPU benchmark:

Run tests with pytest:

### Helper Scripts

Create fixed positions dictionary:
```bash
python helper_scripts/make_fixed_positions_dict.py \
    --input_path=parsed_pdbs.jsonl \
    --output_path=fixed_positions.jsonl \
    --chain_list "A B" \
    --position_list "1 2 3 10 11 12"
```

Assign fixed chains:
```bash
python helper_scripts/assign_fixed_chains.py \
    --input_path=parsed_pdbs.jsonl \
    --output_path=assigned_chains.jsonl \
    --chain_list "A C"
```

Create amino acid bias:
```bash
python helper_scripts/make_bias_AA.py \
    --output_path=AA_bias.jsonl \
    --AA_list "A P" \
    --bias_list "10.0 10.0"
```

## Architecture Overview

### Core Components

**protein_mpnn_run.py**: Main entry point that handles:
- Model initialization with device selection (CUDA/MPS/CPU)
- Input parsing from PDB files or JSONL
- Batch processing and sequence generation
- Output writing in FASTA format

**protein_mpnn_utils.py**: Contains:
- `ProteinMPNN`: Main neural network model using message passing
- `StructureDataset`/`StructureDatasetPDB`: Data loading classes
- `tied_featurize`: Graph featurization for protein structures
- `parse_PDB`/`parse_fasta`: Input parsing utilities
- Loss functions and scoring utilities

**Model Weights**:
- `vanilla_model_weights/`: Standard full-backbone models
- `ca_model_weights/`: CA-only models (use with --ca_only flag)
- `soluble_model_weights/`: Models trained on soluble proteins only

### Key Design Patterns

1. **Graph Representation**: Proteins are represented as graphs where:
   - Nodes = amino acid residues
   - Edges = spatial relationships (k-NN graph, default k=48)
   - Features include backbone coordinates, distances, and angles

2. **Message Passing**: The model uses multiple rounds of message passing to propagate information across the protein structure before making sequence predictions.

3. **Tied Positions**: Supports symmetric design by tying positions together - useful for homo-oligomers.

4. **Chain Masking**: Flexible specification of which chains to design vs. fix during generation.

5. **MPS Support**: Added device detection and compatibility for Apple Silicon GPUs, falling back to CPU when MPS is unavailable.

## Model Parameters

Key command-line arguments:
- `--model_name`: Choose model variant (v_48_002, v_48_010, v_48_020, v_48_030)
- `--sampling_temp`: Controls sequence diversity (0.1=conservative, 0.3=diverse)
- `--num_seq_per_target`: Number of sequences to generate
- `--batch_size`: Sequences per batch (reduce if OOM)
- `--backbone_noise`: Add Gaussian noise to coordinates for robustness
- `--pssm_multi`: Weight for PSSM bias (0.0-1.0)

## Input/Output Formats

**Input**: 
- PDB files (single or multiple chains)
- JSONL with parsed structures
- FASTA files for scoring

**Output**:
- FASTA format with metadata in headers
- Score = negative log probability of designed residues
- Global score = score across all residues
- Seq_recovery = fraction matching native sequence

## Testing Considerations

When running tests on Apple Silicon:
- MPS backend may not support all PyTorch operations
- Some operations automatically fallback to CPU
- GPU memory monitoring requires system tools (ioreg/powermetrics)
- Performance gains are most notable for larger batch sizes

## Dependencies

Core requirements:
- Python >= 3.0
- PyTorch (with MPS support for Apple Silicon)
- NumPy

The codebase doesn't use a formal dependency management file but relies on standard scientific Python stack.
